# Campaign creation persistence

The direct `POST /campaigns` endpoint reports success only after a requested rules mode has been saved and the campaign has been read back. A failed rules write or read returns HTTP 500. An omitted rules mode uses the database default. A failed follow-up write can leave the initial campaign row; callers should inspect their campaign list before retrying this direct endpoint.

World creation requires a character name that is not blank. `world.Orchestrator.Run` refuses one before any model request or write, for both rules versions and for the TUI and the API; `POST /campaigns/start/world` answers HTTP 400. Creation and rename save the name without surrounding white space. Names saved earlier are not trimmed. `PUT /campaigns/{id}/character/name`, with `character_id` and `name`, renames a character for the campaign's owner. It answers 204, 400 for a blank name and 404 for a character outside the campaign, and it works for both rules versions. See [data-checks/blank-character-names.md](data-checks/blank-character-names.md) for characters saved before this rule.
